Variables & Memory Architecture

Beginner Core Model

Core Concept: In Python, variables are references (pointers) to objects in heap memory, not memory boxes holding raw data. When you write x = 10, Python allocates an integer object 10 in heap memory and binds the name x to its memory address.

Immutability vs Mutability: Primitive types (int, float, str, tuple) are immutable—modifying them re-allocates a brand new object. Collections like list, dict, and set are mutable—mutating them changes the object in place, affecting all variables referencing that same memory address.

Visual Workflow: Stack Reference → Heap Object CPython Model
Stack (Names)
a ptr ➔
b ptr ➔
c = [1,2] ptr ➔
➔
Heap (Objects)
int: 10 id: 0x10a8 (shared)
list: [1, 2] Mutable in-place
Python 3 
# Primitive assignment & identity
x = 10
y = x
print(x is y)        # True (both point to same memory address in heap)
print(id(x) == id(y))# True

# Mutable reference aliasing trap
list_a = [1, 2, 3]
list_b = list_a      # Copies POINTER, not the list!
list_b.append(4)
print(list_a)        # [1, 2, 3, 4] -> Both changed!

# Safe independent clone
list_c = list_a.copy() # Shallow clone allocates new heap list
list_c.append(99)
print(list_a)        # [1, 2, 3, 4] -> Unchanged!
📌 Revision Notes & Interview Insights
  • is vs ==: == compares values/equality; is compares memory address identity (id(a) == id(b)).
  • Integer Interning: CPython pre-caches small integers from -5 to 256 in memory. Therefore a = 100; b = 100; a is b is True.
  • Pro Tip: Always use copy.deepcopy() for nested data structures (lists of dicts, 2D arrays).
CPython Memory Heap
Access: O(1) Ref Count: O(1)

Control Flow & Decision Logic

Beginner Branching

Core Concept: Python executes instructions sequentially unless redirected by conditional branching (if/elif/else) or loops (for/while). Python evaluates truthiness using standard falsy values: 0, 0.0, "", [], {}, set(), None, False.

Loop Controls: break immediately terminates the enclosing loop; continue skips the remaining statements of the current iteration and jumps to the next cycle; for...else executes the else block only if the loop terminated naturally without hitting a break.

Execution Flowchart: Loop with Break vs Continue vs Else
1. Loop Start ➔ 2. Condition Check ➔ 3. Condition Met?
break: Abort Loop (skip else) continue: Next Step Finished? Run else
Python 3 
# Short-circuit logic evaluation
# 'and' returns first falsy or last truthy; 'or' returns first truthy
user = None
name = user or "Guest"  # Evaluates to "Guest"

# Elegant For-Else (Search without boolean flag)
numbers = [2, 4, 6, 8, 10]
target = 7

for num in numbers:
    if num == target:
        print(f"Found {target}!")
        break
else:
    # Runs ONLY if the loop finished without encountering a 'break'
    print(f"{target} was NOT found in list!")

# Conditional Expression (Ternary)
status = "Adult" if age >= 18 else "Minor"
📌 Revision Notes & Interview Insights
  • Short-circuiting: In A and B, if A is falsy, B is never evaluated. In A or B, if A is truthy, B is never evaluated.
  • The for-else Pattern: Eliminates boilerplate flags like found = False when searching or checking for prime numbers.
Iteration & Conditions
Branch: O(1) Loop: O(n)

Functions, Scopes & Lambda

Intermediate Execution

Core Concept: Functions are first-class citizens in Python—they can be assigned to variables, passed as arguments, and returned from other functions. Python resolves identifiers using the LEGB Rule (Local → Enclosing → Global → Built-in).

Argument Packing: *args captures extra positional arguments into an immutable tuple; **kwargs captures extra keyword arguments into a dict. Lambda functions provide anonymous, inline single-expression functions.

LEGB Scope Hierarchy & Call Stack Activation
L: Local (Inside def) ➔ E: Enclosing (Closure) ➔ G: Global (Module) ➔ B: Built-in
Python 3 
# Flexible argument packing
def super_logger(prefix, *args, **kwargs):
    # args is a tuple; kwargs is a dict
    msg = " ".join(str(a) for a in args)
    tags = " ".join(f"[{k}={v}]" for k, v in kwargs.items())
    print(f"{prefix}: {msg} {tags}")

super_logger("INFO", "User", 42, "logged in", ip="127.0.0.1", role="Admin")

# DANGEROUS PITFALL: Default mutable argument!
# def append_bad(val, lst=[]):  # BUG: lst created ONCE at def time!
def append_safe(val, lst=None):
    if lst is None:
        lst = []
    lst.append(val)
    return lst

# Higher-order lambdas with map / filter
nums = [1, 2, 3, 4, 5, 6]
evens_squared = list(map(lambda x: x**2, filter(lambda x: x % 2 == 0, nums)))
# Result: [4, 16, 36]
📌 Revision Notes & Interview Insights
  • Default Mutable Trap: Default parameters are evaluated once when the function is defined, not every time it is called. Never write def f(x=[]); always use def f(x=None).
  • Keyword-only arguments: def f(a, *, b): forces caller to pass b as a named keyword argument (f(1, b=2)).
Call Stack Frames
Call: O(1) Stack: O(depth)

Strings & Dual-Index Slicing

Beginner Indexing

Core Concept: Python strings are immutable sequences of Unicode code points. Because they are immutable, concatenating strings in a loop with += creates a new string object on every step ($O(n^2)$ overhead). Always use "".join(list) for $O(n)$ linear efficiency.

Slicing Formula: sequence[start:stop:step] extracts elements from start up to (but excluding) stop, incrementing by step. Negative step moves backward.

Python 3 
s = "PythonDataScience"

# Slicing mechanics
print(s[0:6])         # "Python" (indexes 0..5)
print(s[-7:])         # "Science" (last 7 chars)
print(s[::2])         # "PtoDtSine" (every 2nd char)
print(s[::-1])        # "ecneicSataDnohtyP" (Reverse string)

# Modern f-strings with formatting specifiers
pi, score = 3.1415926, 92.5
print(f"PI: {pi:.2f} | Score: {score:05.1f}") # "PI: 3.14 | Score: 092.5"

# Efficient string joining
words = ["Python", "For", "Data", "Science"]
sentence = " ".join(words) # O(n) runtime, single allocation!

  • Immutability: s[0] = 'J' raises a TypeError. Use s = 'J' + s[1:] or convert to a list first.
  • Reverse String: s[::-1] creates a new reversed string in $O(n)$ time using optimized C slicing.

Lists: Dynamic Array Mechanics

Intermediate Data Structure

Core Concept: Python lists are implemented as contiguous dynamic arrays of 64-bit pointers to heap objects. They support $O(1)$ random index access via pointer arithmetic. When full, CPython reallocates with an over-allocation growth factor (0, 4, 8, 16, 25, 35, 46...) to guarantee amortized $O(1)$ append.

Caution: Inserting or popping at the front (lst.insert(0, val) or lst.pop(0)) requires shifting all $N$ elements right or left, taking $O(n)$ linear time!

Memory Layout: Contiguous Pointers to Dispersed Objects
[0] ptr ➔ "A" [1] ptr ➔ 42 [2] ptr ➔ 3.14 [3] Empty

Contiguous memory holds pointers only. Objects live elsewhere on heap.

Python 3 
# Initialization & operations
lst = [10, 20, 30, 40, 50]

# O(1) Amortized Append & Pop at end
lst.append(60)       # [10, 20, 30, 40, 50, 60]
last = lst.pop()     # 60 removed -> O(1)

# O(n) Expensive front operations
lst.insert(0, 5)     # 5 inserted at index 0 (shifts all elements right)
first = lst.pop(0)   # 5 removed (shifts all elements left) -> O(n)

# List Comprehensions (Faster than for-loop due to C bytecode)
matrix = [[1, 2], [3, 4]]
flattened = [x for row in matrix for x in row]  # [1, 2, 3, 4]

# Sorting: In-place vs New List
lst.sort(reverse=True)            # Modifies lst in-place O(n log n)
new_sorted = sorted(lst, key=abs) # Returns new list
📌 Revision Notes & Interview Insights
  • Queue Warning: Never use list as a FIFO queue (calling pop(0)). Use collections.deque which has double-ended pointers for $O(1)$ push/pop from both ends.
  • Sorting Algorithm: Python uses Timsort (hybrid of Merge Sort and Insertion Sort). It is adaptive ($O(n)$ best case) and stable.
Dynamic Array (Over-allocated)
Append: O(1)* Insert(0): O(n)

Tuples: Immutability & Memory Packing

Beginner Immutability

Core Concept: Tuples are immutable ordered sequences. Once created, their size and element pointers cannot be altered. Because of their immutability, Python allocates exact memory without over-allocation buffers, making them more lightweight than lists.

Hashability & Dict Keys: If a tuple contains only immutable elements, it is hashable and can be used as a key in a dictionary or stored in a set (lists cannot!).

Memory Footprint Comparison: List vs Tuple
list [1, 2, 3] 88 bytes (header + spare buffer)
tuple (1, 2, 3) 64 bytes (exact allocation, read-only)
Python 3 
# Single element tuple syntax requires trailing comma!
t_single = (42,)      # tuple
not_a_tuple = (42)    # int!

# Destructuring & Unpacking
point = (10, 20, 30)
x, y, z = point       # x=10, y=20, z=30

# Star unpacking (rest)
first, *middle, last = (1, 2, 3, 4, 5)
# first=1, middle=[2,3,4], last=5

# Swapping values without temporary variable
a, b = 5, 10
a, b = b, a           # a=10, b=5

# Used as dictionary key (compound coordinate)
grid = {}
grid[(12.5, 45.8)] = "Radar Station Alpha"
📌 Revision Notes & Interview Insights
  • Defensive Programming: Use tuples for data that should never be mutated by downstream consumers (e.g., database connection configs, geometric coordinates).
  • Tuple with Mutable Element: t = ([1, 2], 3) is itself immutable (its pointers cannot change), but t[0].append(99) will mutate the inner list! Such a tuple is NOT hashable.
Fixed Memory Block
Access: O(1) Space: O(n) compact

Dictionaries: Hash Map Mechanics

Intermediate O(1) Lookup

Core Concept: Python dictionaries are ultra-fast hash maps providing average $O(1)$ time complexity for insertion, lookup, and deletion. Under the hood, Python computes hash(key), maps it to a sparse index array, and resolves collisions using open addressing with pseudo-random probing.

Python 3.7+ Feature: Dictionaries strictly maintain insertion order while reducing memory footprint by ~20% compared to legacy versions.

Hash Function Workflow: Key ➔ Hash ➔ Bucket Entry
"Alice" ➔ hash() ➔ Bucket [3] ➔ ('Alice', 95)

Key must be immutable & hashable (strings, numbers, tuples).

Python 3 
# Creation & Safe Access
user = {"id": 101, "name": "Priyanshu", "role": "Engineer"}

# Safe retrieval with fallback (avoids KeyError)
email = user.get("email", "not_provided@domain.com")

# setdefault: inserts key with default IF key doesn't exist
user.setdefault("status", "Active")

# Dictionary Comprehension
squares = {x: x**2 for x in range(6) if x % 2 == 0}
# {0: 0, 2: 4, 4: 16}

# Modern Merge Operator (Python 3.9+)
defaults = {"theme": "dark", "fontSize": 14}
custom = {"fontSize": 16, "fontFamily": "Mono"}
merged = defaults | custom  # custom overrides defaults
📌 Revision Notes & Interview Insights
  • Runtime Complexity: Lookup, insert, and delete are all $O(1)$ average. Degrades to $O(n)$ only under catastrophic hash collisions.
  • Iteration Guard: Never add or remove keys from a dictionary while looping over it (raises RuntimeError: dictionary changed size during iteration). Use list(d.keys()) instead.
Hash Table with Open Addressing
Search: O(1) Insert: O(1)

Sets: Hash Sets & Venn Operations

Beginner Set Theory

Core Concept: Sets are unordered collections of unique, hashable elements. They are internally implemented as hash tables with dummy values. Checking x in my_set runs in $O(1)$ instantaneous time, whereas x in my_list takes $O(n)$ linear time scanning all elements.

Mathematical Set Theory: Sets support rich mathematical operations: Union ($\cup$), Intersection ($\cap$), Difference ($-$), and Symmetric Difference ($\Delta$).

Set Venn Operations (Set A vs Set B)
A | B (Union: All) A & B (Intersect: Both) A - B (Diff: In A only) A ^ B (Sym: Not in both)
Python 3 
A = {1, 2, 3, 4}
B = {3, 4, 5, 6}

print(A | B)    # Union: {1, 2, 3, 4, 5, 6}
print(A & B)    # Intersection: {3, 4}
print(A - B)    # Difference: {1, 2}
print(A ^ B)    # Symmetric Difference: {1, 2, 5, 6}

# Safe removal vs KeyError removal
A.discard(99)   # Safe: does nothing if 99 is missing
# A.remove(99)  # Raises KeyError!

# Fast deduplication of lists
raw_items = ["apple", "banana", "apple", "orange", "banana"]
unique_items = list(set(raw_items))  # ['apple', 'banana', 'orange']

# Immutable Set for dictionary keys
frozen = frozenset([1, 2, 3])  # Hashable!
📌 Revision Notes & Interview Insights
  • Empty Set Syntax: s = {} creates an empty dict, NOT a set! You MUST use s = set().
  • Membership Optimization: Always convert lists to sets if you perform frequent if item in collection lookups inside a loop ($O(1)$ vs $O(n)$).
Hash Table (Keys-Only)
Lookup: O(1) Union: O(len(s)+len(t))

Stacks & Linked Lists (DSA)

Intermediate DSA Core

Stack (LIFO): Last-In, First-Out data structure. Used in undo operations, browser history, and function call execution. Implemented efficiently with collections.deque.

Linked List: Linear sequence of node objects where each node contains data and a next pointer. Singly linked lists allow forward traversal; Doubly linked lists add a prev pointer. They offer $O(1)$ insertion at the head without memory reallocation.

Node Chain: Singly Linked List Architecture
[Head] ➔ [10 | next] ➔ [20 | next] ➔ [30 | NULL]
Python 3 
# 1. High-Performance Stack using Deque (O(1) push & pop)
from collections import deque
stack = deque()
stack.append("A")     # Push
stack.append("B")
top = stack.pop()     # Pop -> "B" (O(1))

# 2. Singly Linked List Node Implementation
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class LinkedList:
    def __init__(self):
        self.head = None

    def insert_head(self, data):
        new_node = Node(data)
        new_node.next = self.head
        self.head = new_node  # O(1) Head Insertion!
📌 Revision Notes & Interview Insights
  • Array vs Linked List: Arrays have $O(1)$ random indexing but $O(n)$ insertion/deletion. Linked Lists have $O(1)$ pointer insertion at head/tail but $O(n)$ search (no random access).
  • LeetCode Pattern: Fast and Slow Pointers (Floyd's Cycle Detection) can find middle of linked list or detect loops in $O(n)$ time and $O(1)$ space.
Linear Pointer Structures
Push/Pop: O(1) LL Search: O(n)

OOP Architecture & 4 Pillars

Advanced OOP Master

Core Concept: Object-Oriented Programming models systems as cooperating objects with state (attributes) and behavior (methods). Python supports all 4 pillars:

1. Encapsulation: Bundling data and methods; restricting direct access with private __attributes and @property getters/setters.
2. Abstraction: Exposing only essential interface details via abc.ABC and @abstractmethod.
3. Inheritance: Reusing logic through class hierarchies using super() and MRO.
4. Polymorphism: Same method call behaving differently based on the receiving object (duck typing).

Architecture: The 4 Pillars of OOP
1. Encapsulation (__private) 2. Abstraction (ABC) 3. Inheritance (super) 4. Polymorphism
Python 3 
from abc import ABC, abstractmethod

# 1. Abstraction (Blueprint contract)
class PaymentProcessor(ABC):
    @abstractmethod
    def pay(self, amount: float):
        pass

# 2. Inheritance & Encapsulation
class CreditCardProcessor(PaymentProcessor):
    def __init__(self, card_number: str):
        self.__card_number = card_number # Private attribute

    @property
    def masked_card(self): # Encapsulated getter
        return f"****-****-****-{self.__card_number[-4:]}"

    # 3. Polymorphism (Override)
    def pay(self, amount: float):
        return f"Paid ${amount:.2f} via {self.masked_card}"

# Polymorphic usage
proc: PaymentProcessor = CreditCardProcessor("1234567890123456")
print(proc.pay(150.0)) # "Paid $150.00 via ****-****-****-3456"
📌 Revision Notes & Interview Insights
  • Name Mangling: self.__x is transformed internally to _ClassName__x to prevent accidental overriding in subclasses.
  • MRO (Method Resolution Order): Python uses the C3 Linearization algorithm to resolve multiple inheritance collisions (check via Class.__mro__).
Dynamic Dispatch / Duck Typing
Method Call: O(1) MRO Lookup: O(depth)

OOP Dunder (Magic) Methods

Advanced Operator Overload

Core Concept: Dunder (Double Underscore) methods allow your custom classes to seamlessly integrate with Python's core syntax and protocols (e.g. len(), +, ==, with context managers, str()).

__repr__ vs __str__: __repr__ is for developers—it must be unambiguous and ideally valid Python code to recreate the object. __str__ is for end users—it should be clean and readable.

Python Syntax to Dunder Method Dispatch
len(obj) ➔ __len__ a + b ➔ __add__ a == b ➔ __eq__ with x: ➔ __enter__
Python 3 
class Vector2D:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f"Vector2D({self.x}, {self.y})" # Unambiguous

    def __str__(self):
        return f"({self.x}, {self.y})"        # User-friendly

    def __add__(self, other): # Overloads '+'
        return Vector2D(self.x + other.x, self.y + other.y)

    def __eq__(self, other):  # Overloads '=='
        return self.x == other.x and self.y == other.y

v1 = Vector2D(3, 4)
v2 = Vector2D(1, 2)
v3 = v1 + v2
print(v3)            # "(4, 6)"
print(repr(v3))      # "Vector2D(4, 6)"
📌 Revision Notes & Interview Insights
  • Context Managers: Implementing __enter__ and __exit__ enables the with statement, guaranteeing resource release (files, locks, DB sockets).
  • Fallbacks: If __str__ is not defined, Python falls back to __repr__ automatically.
Special Method Protocol
Dispatch: O(1)

Adaptive vs Non-Adaptive Sorting

Intermediate Algorithm Core

Adaptive Algorithm: Takes advantage of existing order in the input data. If given an already sorted or nearly sorted list, it detects the order and finishes early in $O(n)$ linear time. Examples: Insertion Sort, Optimized Bubble Sort, and Timsort.

Non-Adaptive Algorithm: Performs the exact same sequence of comparisons and operations regardless of whether the array is completely sorted, randomized, or reverse sorted. Example: Selection Sort (strictly $O(n^2)$ always) and standard Merge Sort ($O(n \log n)$ always).

Animated Workflow: Adaptive Early Exit vs Non-Adaptive Scan
✅ Adaptive (Insertion Sort)
Already sorted? Inner loop breaks immediately ➔ O(n) Best Case!
❌ Non-Adaptive (Selection Sort)
Already sorted? Blindly compares all n(n-1)/2 pairs anyway ➔ O(n²) Always!
Python 3 
# 1. ADAPTIVE: Optimized Bubble Sort (O(n) on sorted data)
def adaptive_bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        swapped = False
        for j in range(0, n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True
        # If no swaps occurred, array is already sorted! Exit early!
        if not swapped:
            break
    return arr

# 2. NON-ADAPTIVE: Selection Sort (O(n²) always)
def selection_sort(arr):
    n = len(arr)
    for i in range(n):
        min_idx = i
        # Always scans all remaining elements even if sorted!
        for j in range(i + 1, n):
            if arr[j] < arr[min_idx]:
                min_idx = j
        arr[i], arr[min_idx] = arr[min_idx], arr[i]
    return arr
📌 Revision Notes & Interview Insights
  • Adaptive Winners: Insertion Sort and Bubble Sort with a swapped flag. Both run in $O(n)$ time when input is already sorted!
  • Non-Adaptive Reality: Selection Sort always does $\frac{n(n-1)}{2}$ comparisons regardless of input ordering.
  • Stability: An algorithm is stable if it preserves the relative order of duplicate elements. Bubble, Insertion, and Merge Sort are stable; Selection Sort and standard Quick Sort are unstable.
Sorting Classifications
Best: O(n) Adaptive Worst: O(n²)

Searching: Binary vs Linear

Beginner Searching

Linear Search ($O(n)$): Sequentially inspects each item from start to finish. Works on unsorted or sorted data.

Binary Search ($O(\log n)$): Requires a sorted array. Operates by repeatedly dividing the search range in half. In an array of 1,000,000 items, Linear Search takes up to 1,000,000 checks, while Binary Search takes at most 20 checks!

Binary Search: Search Space Halving (N ➔ N/2 ➔ 1)
1000 items ➔ 500 items ➔ 250 items ➔ ... ➔ Found (10 checks)
Python 3 
# Binary Search (Iterative Implementation)
def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

# Using Python's standard library bisect
import bisect
sorted_arr = [10, 20, 30, 40, 50]
idx = bisect.bisect_left(sorted_arr, 30) # 2 (O(log n))
📌 Revision Notes & Interview Insights
  • Prerequisite: Binary Search strictly requires a sorted array. If the array is unsorted, sorting it takes $O(n \log n)$, which is slower than a single linear search ($O(n)$) for one-off lookups.
  • Integer Overflow Guard: In languages with fixed integer sizes, write mid = low + (high - low) // 2 to prevent overflow.
Divide and Conquer
Linear: O(n) Binary: O(log n)

Big-O Complexity Master Reference

Advanced Complexity

Core Concept: Big-O notation describes the upper bound of time or memory growth as input size $N$ scales to infinity. The efficiency hierarchy from best to worst is: $O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(2^n)$.

Algorithm Best Average Worst Space Adaptive?
Bubble Sort O(n) O(n²) O(n²) O(1) ✅ Yes
Insertion Sort O(n) O(n²) O(n²) O(1) ✅ Yes
Selection Sort O(n²) O(n²) O(n²) O(1) ❌ No
Merge Sort O(n log n) O(n log n) O(n log n) O(n) ❌ No
Quick Sort O(n log n) O(n log n) O(n²) O(log n) ❌ No
📌 Revision Notes & Interview Insights
  • Time-Space Trade-off: Merge Sort guarantees $O(n \log n)$ worst-case time, but requires $O(n)$ extra memory buffer for merging. Quick Sort requires only $O(\log n)$ recursion stack memory, but can degrade to $O(n^2)$ if pivot is picked poorly.
  • Counting Sort: Non-comparison integer sort running in $O(n + k)$ where $k$ is the range of values.
Asymptotic Analysis
Timsort: O(n log n)

NumPy: Vectorization & SIMD

Intermediate Data Science

Core Concept: NumPy replaces slow Python pointer-based lists with homogeneous, contiguous C-memory ndarray blocks. Vectorized operations run directly via compiled C/Fortran SIMD (Single Instruction, Multiple Data) instructions, running 50x to 100x faster than standard Python for loops.

Broadcasting: Automatically aligns dimensions of different shaped arrays without copying data.

Memory Layout: Python Pointer List vs NumPy Contiguous C Array
Python List Scattered heap pointers
NumPy Array Contiguous C memory block
Python 3 
import numpy as np

# 1. Array Creation & Reshaping
a = np.array([1, 2, 3, 4, 5, 6])
matrix = a.reshape(2, 3) # 2 rows, 3 columns

# 2. Vectorized Operations (No loops!)
squared = matrix ** 2
col_sums = np.sum(matrix, axis=0) # Sum down columns
row_means = np.mean(matrix, axis=1) # Mean across rows

# 3. Broadcasting (1D vector added to 2D matrix)
bias = np.array([10, 20, 30])
result = matrix + bias # Broadcasts bias across both rows!

# 4. Boolean Mask Filtering
filtered = matrix[matrix > 3] # [4, 5, 6]
📌 Revision Notes & Interview Insights
  • Views vs Copies: Basic slicing in NumPy (b = a[1:4]) produces a view, NOT a copy. Modifying b mutates a! Use b = a[1:4].copy() to detach.
  • Broadcasting Rule: Two dimensions are compatible if they are equal, or one of them is 1.
Contiguous C Buffer

Pandas: DataFrames & Data Wrangling

Intermediate Data Science

Core Concept: Pandas provides fast, flexible 2D tabular data structures: Series (1D labeled column) and DataFrame (2D table with labeled row index and column headers). Built on top of NumPy arrays with relational algebra support (filter, merge, join, groupby).

loc vs iloc: .loc[] indexes by label (inclusive of both endpoints); .iloc[] indexes by integer 0-based position (exclusive of stop endpoint).

2D Tabular Anatomy: Index (Axis 0) & Columns (Axis 1)
[Index (Rows: axis 0)] ✕ [Columns (Series: axis 1)]

import pandas as pd

# Indexing: loc (label) vs iloc (integer position)
top_student = df.loc[df["score"] > 90, ["name", "score"]]
first_row_third_col = df.iloc[0, 2]

# GroupBy Split-Apply-Combine Pattern
dept_avg = df.groupby("department")["salary"].mean()
